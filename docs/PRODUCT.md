# Padora — プロダクト定義 & 開発ロードマップ

## 1. プロダクト概要

| 項目 | 内容 |
|------|------|
| 名称 | Padora |
| 一言 | 操作は片手に任せて、ゲームに集中 — PC版 WOLF / ツクール向け専用コントローラー |
| 対象 | キーボード操作に不便を感じるウディタプレイヤー（まずは自分用） |
| 形態 | Androidアプリ ＋ Windows受信ソフト |
| 立ち位置 | 非公式の入力支援ツール（公式・公認ではない） |

**やること**  
スマホ画面の少ボタン操作を、PCへキーボード入力として送る。

**やらないこと（初期）**  
ゲーム実行・エミュレート、多機能リモコン化、公式ロゴ／素材利用、ボタンの多機能化。

**現在のゴール**  
自分用MVP：USBテザリング＋少ボタンで、手元のウディタがストレスなく遊べる。

---

## 2. プロダクト方針

### コア方針
1. **操作は最小・単純** — ストレスを減らすことが価値
2. **片手操作** — マウス感覚で使える
3. **無料＝最速（有線）** — 遅延不満を構造的に避ける（将来公開時）
4. **有料＝手軽さ（無線）＋カスタム** — 利便性で課金（将来）
5. **無線も遅延は極力低減** — 有料でも体感差を小さくする

### 無料 / 有料（将来公開時）

| | 無料 Padora | 有料 Padora Pro |
|--|------|------|
| 接続 | 有線（USBテザリング）／手動IP（Tailscale等） | Wi‑Fi無線（同一LAN・自動検出） |
| パッド UI | **十字＋4ボタン**（決定・取消・Shift・カスタム1） | **十字＋最大6ボタン**（大4＋小2） |
| 上部チップ | F4 / F11 **固定** | **任意キーに差し替え可**（例: F4＋Ctrl） |
| キー割り当て | 単一構成（設定画面で変更可） | 複数プロファイル（作品別） |
| ショートカット | 単キーのみ | 複合キー・斜め（2キー同時押し） |
| レイアウト | ボタン左右反転（十字は固定）— **無料** | プロファイルごとに反転設定を記憶 |
| 画面サイズ | スマホ／閉じたフォルダブル想定（大画面は UI を引き伸ばさない、480dp cap） | 同左 |
| 見た目 | 標準テーマ | カラーカスタム |
| バックアップ | 現在の1構成のみ書き出し／読み込み | 複数プロファイル一式の書き出し／読み込み |
| 狙い | 最速・すぐ遊べる | ケーブルなし＋作品ごとの最小キーセット＋設定の持ち運び |

### v1 無料版（ストア公開の芯）

| 項目 | v1 で入れる | v1 後（v1.1 等） |
|------|-------------|------------------|
| 十字＋4ボタン | ○ | — |
| 1マス短パルス（42ms 常時） | ○ | — |
| 接続（Tailscale / 有線・IP 記憶） | ○ | 切断・自動再接続は後 |
| 署名・法務・Host 配布 | ○ | — |
| 十字キー（十字レイアウト・デッドゾーンなし） | ○ | — |
| UI maxWidth cap（phone-size） | ○ | — |
| ボタン左右反転（十字固定） | ○ | — |
| 斜め移動 | — | Pro の chord または要望ベース |
| Pro（6ボタン・無線・プロファイル） | — | S6・需要見てから |

**想定ユーザー:** 古いスマホを **専用コントローラー** にして、PC 版 WOLF / ツクール系を片手・視線オフで遊ぶ人。

**想定していない用途:** 格闘・FPS・3Dアクションなど、**多数のキー入力やスティック（アナログ）操作が必要なゲーム**。仮想スティックや多ボタンパッド化はしない。

**コンセプトとの一致:** 片手操作を最大の売りにするため、UI は **通常スマホ／フォルダブル閉じたサイズ**（最大 480dp）に統一し、タブレット・大画面でパッドを引き伸ばさない。

自分用フェーズでは課金・公開整備は行わない。有線（USBテザリング＋UDP）を最優先する。

### バックアップ／リストア（Pro と同時実装）

プロファイル機能（作品別のキー・色など）を Pro で入れる場合、**ローカルの書き出し／読み込み**を同じタイミングで付ける。

| 項目 | 方針 |
|------|------|
| 方式 | 端末内の **JSON ファイル**（Android の共有・ファイル選択） |
| ファイル例 | `padora-backup-v1.json`（先頭に **スキーマ version** を必ず含める） |
| 含める | プロファイル名、キー割り当て、色（Pro）、触覚 ON/OFF、テーマなど |
| 含めない | 最後に使った IP（環境依存のため接続画面で都度入力） |
| 無料 | 現在の **1 構成だけ** export / import（機種変更・再インストール用） |
| Pro | **複数プロファイル一式**の export / import |
| UI | 設定画面に「設定を書き出す」「設定を読み込む」の 2 項目（クラウド同期は v1 不要） |
| 後回し | Google Drive 連携、自動同期、アカウント連携 |

**理由:** Pro の価値は「複数プロファイルの蓄積」にある。機種変更で消えると Pro として弱い。一方、最初からクラウドまで作るとスコープが膨らむため、**JSON のローカル export/import だけ**で MVP Pro に足す。

## 3. 操作設計

### 公式必須操作（採用）

| 操作 | デフォルト送信キー | UI |
|------|-------------------|-----|
| 移動 | ↑ ↓ ← → | 十字 |
| 決定 | `Z` | ボタン |
| キャンセル（メニュー含む） | `X` | ボタン |
| サブ | `Shift` | 小さめボタン（ラベルなし） |

- **Esc専用ボタンは置かない**（キャンセル＝Xで足りる）
- Esc固定の作品は **将来のキーカスタム** で対応
- F4 / F11 は **上部チップ**（無料・固定）。Pro で任意キーに差し替え可

### UIレイアウト方針
```
[ 十字（移動） ]     [ 決定 ]
                     [ 取消 ]
                     [ サブ ]  ← 端・小さめ可
```
- 右手片手想定（親指＝移動、他指＝決定／取消）
- 最低限は「十字＋決定＋取消」でも成立。サブは目立たせすぎない

### 触覚（短タップのみ）
- **対象:** 十字・決定・取消（Shift / カスタム / F キーは対象外）
- **短タップ（約 220ms 未満）:** 振動あり（盲操作用。十字は最弱パルス）
- **長押し（移動・ダッシュ・スキップ）:** 振動なし
- 設定で ON/OFF。斜め移動の精度より、単方向＋ Z/X ＋ 一部 F キーを優先

### 十字キー：1 マスタップ
- **短タップ（220ms 未満）:** 離した瞬間に固定長（**42ms**）のキーパルス → **1 マス移動**（常時ダッシュ作品でも行き過ぎを抑える。設定なし）
- **長押し（220ms 以上）:** 従来どおり押しっぱなし → フロア／マップの長距離移動
- キーボードより「意図した 1 マス」を再現しやすくするのが目的
- 42ms で反応しない作品への報告があれば、その時点で互換モード等を検討

### 接続（Tailscale / 有線）
- **自分用:** USB テザリング ＋ **Tailscale** の PC IP（`100.x.x.x`）で接続
- **前回 IP:** 接続**成功時のみ**端末内に保存 → 次回起動時に入力欄へ自動入力
- **自動接続:** 設定で ON にした場合のみ起動後に接続（**デフォルト OFF**）
- **削除:** 設定「保存した IP を消す」で端末内クリア（クラウド同期なし）
- Host 画面の IP（Tailscale 側）を入力。スマホ自身の IP ではない

## 4. 技術方針

| 層 | 方針 |
|----|------|
| Android | Flutter、少ボタンUI、押下／離上を送信 |
| 通信（自分用MVP / 将来無料） | USBテザリング上のUDP（無線とロジック共通化） |
| 通信（将来有料） | Wi‑Fi（同一LAN）、ペイロード最小、新鮮さ優先 |
| PC | C# (.NET) トレイ常駐 → `SendInput` でキー注入 |
| 設計原則 | 有線／無線でUIとキー処理を共用し、差は接続層だけにする |

### 有線の実装方針
- **採用:** USBテザリング ＋ UDP（Approach A）
- **見送り:** ADB必須構成、AOA（公開ハードル・実装コスト）

### 無線の遅延低減（将来）
- UDP＋押下／離上イベント
- 同一LAN、自動発見（mDNS / QRなど）
- 最小パケット（ボタンID・状態・連番）
- PC側は即キー注入
- 過剰な再送はしない

- 公式ロゴ・素材・「公式／公認」表現は使わない
- アプリ名は独自名称「Padora」（エンジン名そのものは使わない）
- 説明文で「WOLF RPGエディター製ゲーム向け」など互換表現にとどめる
- ゲーム配布・解析はしない

## 6. 競合ポジション

| 代替 | 本プロダクトの差 |
|------|------------------|
| 汎用リモコン（WiFi Mouse等） | 設定が多く、ウディタに過剰 |
| 物理パッド＋JoyToKey等 | 手元のスマホで完結しない |
| Winlator仮想パッド | PC本体プレイ向けではない |

→ **「ウディタ特化・少ボタン・片手・有線優先」** で差別化。
